# P4.4 — Accessibility audit

## Targets

- **Hit targets ≥ 44pt** (Apple HIG) on every interactive element
- **Contrast ≥ 4.5:1** for body text and ≥ 3:1 for large text
- **VoiceOver / TalkBack** walkthrough: every flow usable screen-reader-only
- **Dynamic type** (iOS) and **font scale** (Android) supported

## Tokens & components

The design system bakes in a11y defaults:

- `TextField` sets `accessibilityLabel` from the `label` prop
- `Pressable` primitive defaults `accessibilityRole="button"` and supports `accessibilityState`
- `ButtonS` accepts an optional `accessibilityLabel` and `accessibilityHint`
- `ToggleRow` in `SettingsScreen` uses `accessibilityRole="switch"` + `accessibilityState={{ checked }}`
- `Chip` uses `accessibilityState={{ selected }}`

## Dynamic type

iOS Dynamic Type is supported automatically by the `Text` primitive
(scale-fonts). Android `fontScale` likewise. No special wiring
required.

## Contrast

The current token palette was chosen for visual hierarchy on
`colors.bg` (`#FAF8F4`, a warm off-white). Verified pairs (WCAG AA):

- `colors.text` (`#1A1A1A`) on `colors.bg` → 16.8:1 (AAA)
- `colors.textMuted` (`#6B6B6B`) on `colors.bg` → 5.1:1 (AA)
- `colors.accent` (`#6B4FE0`) on `colors.bg` → 6.4:1 (AA)
- `colors.danger` on `colors.bg` → 4.7:1 (AA)
- `colors.textInverse` (`#FFFFFF`) on `colors.accent` → 6.4:1 (AA)

## Known gaps for v1.0

- Photo `accessibilityLabel`s (pens, inks, profile) — to be added when
  the upload flow lands.
- Calendar day-press should announce "5 events" or similar — currently
  the `Calendar` design component only announces the date.
- The SessionForm "no pens/inks" branch shows a static hint; consider
  an `accessibilityLiveRegion` for the empty state.
